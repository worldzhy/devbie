## 3. 结论摘要

五闸方向正确，但都是**判定点声明**，缺三类工程内容：**语义定义**（怎么算越界/怎么算失败）、**自保护**（闸门自身被改/崩溃时怎么办）、**依赖闭环**（闸门之间互相兜底的地方没写）。

其中三条是结构性的（未独立复核，建议 P1）：

1. **闸门 1 只校验 `designRef` 非空**，不校验其可解析、仍生效、未被取代；且 `impact` 若在开工后可改，`changeClass` 可被降级回到 `SIMPLE`，准入形同虚设。
2. **闸门 5 依赖闸门 2 的路径排除，但 `scopePaths` 未禁止 `.github/workflows/**` 与 `deploy/**`**。agent 改流水线或部署脚本，即可在闸门之外执行任意命令——全部五闸同时失效。
3. **五闸均未声明 fail-closed 与自保护**。闸门脚本自身被删改、CI 被跳过、判定进程异常时，按通过处理是最省事的实现路径，也正是 agent 会选择的路径。

第四条（建议 P1）：闸门 3 只防数量下降，不防**弱化**——新增 `skip`/`only`、断言降级、把断言挪进不执行分支，数量反而上升。

## 4. 逐闸评估

### 闸门 1：无 `designRef` 不开工

现有：`PENDING → DEVELOPING` 时服务端状态机 + dispatcher 预过滤；失败标 `BLOCKED` 并通知。

| 缺口 | 说明 |
| --- | --- |
| 只判非空 | 指向不存在的路径、指向已 `Superseded` 的 ADR、指向本次已失效的章节，均判通过 |
| `impact` 可变窗口 | `changeClass` 由 `impact` 推导，若 `impact` 在 `DEVELOPING` 后可写，agent 清空四元组即从 `DESIGNED` 降为 `SIMPLE`，`designRef` 校验被一步绕过 |
| 父子继承未定 | 子任务的 `designRef` 是继承父任务还是各自声明，未写；各自声明等于给每个子任务一次豁免机会 |
| 验收标准时点偏晚 | D2 规定 `acceptanceCriteria` 在「进入 TESTING 前」必填；缺验收标准时开工才最容易跑偏，闸门位置应前移到开工 |

增补建议：
- 校验升级为「可解析 + 状态为生效 + 未被取代」，判定逻辑与 `adr-placement` 的 Status 语义对齐。
- `impact` / `scopePaths` / `changeClass` 在 `PENDING → DEVELOPING` 转换后**冻结**，改动只能由人且必须记录（否则计入闸门 4）。
- 子任务 `designRef` 默认继承父任务，仅当显式声明时才可不同，且不同则 `changeClass` 不得为 `SIMPLE`。
- `acceptanceCriteria` 与 `designRef` 同闸校验。

### 闸门 2：改动超出 `scopePaths`

现有：提交前本地校验（快速失败）+ PR CI 复检（权威）；失败停手退回 DEVELOPING 并附差异清单。

| 缺口 | 说明 |
| --- | --- |
| 匹配语义未定义 | 前缀目录还是 glob？`src/modules/x` 与 `src/modules/x/**` 是否等价？重命名（delete+add）如何计入？CI 必须用 `git diff --name-status -M` 才能看见 rename/delete |
| 只有正向集合 | 只判「实际 ⊆ 允许」，未判「允许集是否被删除了本不该删的文件」。删测试若落在允许目录内，闸门 2 看不见，只能靠闸门 3 |
| 空集与超宽集 | `scopePaths: []` 或 `["**"]` 让闸门退化为永真。需要下限（≥1 条、必须指向模块内路径）与上限（禁止仓根通配） |
| 必然变动未豁免 | lockfile、生成物、`migrations/` 常必然变动；不加全局豁免则每天误停，加错豁免则留后门。豁免清单必须显式且排除 `migrations/` |
| 未排除高权路径 | `.github/workflows/**`、`deploy/**`、`prisma/schema.prisma` 若在允许集内，闸门 5 与 schema 约束同时失效 |

增补建议：
- 定义匹配规则为正则/glob 的显式形式，并在 CI 与本地共用同一实现（单一函数，避免两层语义漂移）。
- 增加**禁止路径清单**（workflows、deploy、CI 配置、闸门自身脚本），任何 `scopePaths` 含之即建任务失败——这是闸门 5 的前置条件。
- `--name-status` 视角审查删除与重命名，删除需在 `impact` 中额外声明。
- `DESIGNED` 任务额外要求 `scopePaths` 每条可映射到验收标准的一条，否则视为超宽。

### 闸门 3：测试数 / 断言数下降

现有：PR CI，对比 dev 的 merge-base；PR 红，阻断自动合并。

| 缺口 | 说明 |
| --- | --- |
| 只防减不防弱 | 新增 `it.skip` / `describe.skip` / `fit` / `todo`、把 `toBe(1)` 改成 `toBeDefined()`、把断言挪进不执行分支——计数不降反升 |
| 计数口径 | 参数化/表驱动测试的计数方式未定义；AST 与正则的差集未说明，易被注释掉的测试骗过 |
| 基线不稳 | 用 `merge-base` 而非 PR base sha，dev 前进后基线漂移 |
| 拆分绕过 | 一个测试文件拆成两个，总数上升但覆盖下降；计数无法发现 |

增补建议：
- 新增独立检查项：**禁用标记新增数必须为 0**（`skip`/`only`/`todo`/`xdescribe` 等）。
- 断言强度用白名单反向检查：`toBeTruthy`/`toBeDefined`/`not.toThrow` 的**净增**计数纳入红灯。
- 计数与覆盖率同时看：计数不降但覆盖率下降 → 告警（首版可只记录不阻断，避免噪声）。
- 基线固定为 PR 的 base sha。
- （合法删除测试的豁免通道已登记 R8-09，此处不重复。）

### 闸门 4：失败超预算

现有：同类失败连续 2 次 / 累计 600 行 / 墙钟 45 分钟 / 3 次 push；计数器持久化、只有人可 reset。

| 缺口 | 说明 |
| --- | --- |
| 指纹归一化规则缺失 | 「闸门编号 + 归一化错误摘要」中的归一化未定义。含时间戳、行号、随机 ID 的错误每次都是「不同失败」，连续计数永不触发 |
| 墙钟口径 | 从 worktree 创建到 push，把模型排队、网络抖动、CI 等待都算进去，会误杀；且 45 分钟是单值，无续期机制 |
| 600 行的生成物判定 | 按「排除 `dist/`、生成物」执行时，agent 可把代码写进 `*.generated.ts` 绕过。必须是路径白名单，不是文件名匹配 |
| 3 次 push 与常规操作冲突 | rebase 到最新 dev、修正 commit message 都会消耗预算，正常流程即触发 |
| 缺「无进展」维度 | 反复读文件、跑同一条命令而不失败也不推送，四阈值都不触发，只能靠墙钟兜底 |
| 成本维度缺模型侧 | 待决第 3 项只提 CI 分钟数，未把模型 token 计入预算 |

增补建议：
- 归一化规则写成可测函数：去除时间戳、UUID、绝对路径、行号列号后取 SHA，并附单元测试。
- 墙钟改为「有效执行时间」或给一次人工续期；把 rebase 类操作从 push 计数中排除。
- 600 行的排除项改为路径白名单（含 `dist/`、`*.lock`、快照目录），未命中白名单一律计入。
- 增加「无进展」计数：连续 N 次工具调用无文件变更即计入，与墙钟互补。
- 阈值写进 dispatcher 常量的同时记录每次触发的实际分布，首月回填 P50/P90 校准（并把 token 成本一并观测）。

### 闸门 5：破坏性命令与凭证越界

现有：命令代理 + 凭证最小化 + 出站白名单（ruleset 仅作 git 维度补充）。

| 缺口 | 说明 |
| --- | --- |
| 与闸门 2 的依赖未写 | 不改工作流就绕不过命令代理；但能改 `.github/workflows/**` 与 `deploy/**` 时，代理形同虚设 |
| 白名单方向未定 | deny-list 易漏（`sh -c`、管道、编码执行）；应给 allow-list 最小集 |
| push 作用域未定 | agent 仍需 push 凭证，该凭证必须限单仓 + `task/*` 前缀；force-push 到 dev/main 必须在代理层按 refspec 拒绝，不能只靠 ruleset |
| 依赖安装即执行 | 放行 registry 后，`npm install` 的生命周期脚本就是任意代码执行；需 `--ignore-scripts` 或预装依赖 |
| 数据面未隔离 | 未写 agent 容器不得注入生产 `DATABASE_URL`；否则 `prisma migrate reset` 是比 `s3 rm` 更快的破坏路径 |

增补建议：
- 明确「闸门 5 依赖闸门 2 的禁止路径清单」，两者写成同一条不变量，缺一即视为闸门 5 未闭合。
- 命令代理采用 allow-list，最小集：构建/测试/lint/只读 git/向 `task/*` push；其他一律拒绝并记录。
- git 凭证按仓 + 分支前缀限权；代理层校验 refspec。
- 依赖安装固定 `--ignore-scripts`，镜像内预装依赖。
- 容器 env 白名单化，生产连接串与 AWS 凭证在构建期就不可达（不是运行时判断）。

### 跨闸共性问题

1. **fail-closed 未声明**：任何闸门异常、跳过、超时都应按「未通过」处理，并阻断流转。这是最容易被实现成 fail-open 的一处。
2. **闸门自保护缺失**：闸门 2/3 的判定脚本若与业务代码同仓可写，agent 可改判定逻辑。闸门脚本应位于受保护路径，CI 校验其自身未被本次 PR 修改。
3. **override 通道缺失**：五闸都没有「人工豁免并留痕」的正式通道。没有通道不等于不会绕过，只会让绕过发生在闸门之外（改配置、改脚本、`--no-verify`），且不留痕。应提供仅人可用的 override + 审计日志。
4. **闸门之间的短路与累计规则**：闸门 2 停手后是否计入闸门 4 失败计数，只在 D3 局部写了「重复触发计入」，未成文为全局规则。

## 6. 已核验通过的不变量

- 闸门 1、4 的判定者确实是外部（状态机只看字段、预算只由 dispatcher 计数），agent 无法自报通过——这是 D4 分层理由的正确部分。
- 闸门 2、3 双层设计成立：本地缩短漂移窗口、CI 防 `--no-verify`，两层价值不重复。
- 闸门 5 已撤回 ruleset 硬闸的错误声明（round8 修复有效），方向正确。
- 闸门 4 的计数器持久化 + 仅人可 reset，堵住了「agent 重置预算」这条路径。

## 8. 修复优先级

1. 禁止路径清单（R9-02）——它是闸门 5 与闸门 2 的共同前置，成本最低、收益最大。
2. fail-closed + 闸门自保护（R9-03）——决定其余四闸是否真的存在。
3. 闸门 1 的可解析性校验与字段冻结（R9-01）——堵住准入被降级。
4. 闸门 3 的弱化检测（R9-04）——补上「不删测试也能让测试失效」这条主路径。
5. 语义与口径类（R9-05/06/07/08/09）——实现前补齐即可，不阻塞设计定稿。
